Context Parameters — Quick Reference

Stable · Kotlin 2.4 ← Lesson 1

Declaration

context(name: Type)
fun myFunction(arg: Arg): Result { /* name is in scope */ }

Multiple contexts

context(a: TypeA, b: TypeB)
fun myFunction() { /* both a and b in scope */ }

On a class

context(scope: CoroutineScope)
class MyClass { /* scope available in all members */ }

Providing context at call site

with(myLogger) {
    processOrder(order)   // Logger is now in scope
}

// Or inside another context(logger: Logger) fun

Explicit context argument (experimental)

// Two overloads differ only by context type → disambiguate:
sendNotification(emailSender = myEmailSender)

vs. Extension functions

Use extension when… Use context when…
Function belongs to the type Type is an ambient dependency
Single context makes sense Multiple contexts needed
You own the type's API surface Adding to the type would pollute it

Common use cases

  • Logging / tracing (Logger, Span)
  • Transaction / session scope
  • Coroutine scope injection
  • DSL builders with implicit configuration
  • Type-class patterns (capability evidence)
